BÀI 23

Guardrails: kiểm soát trước, trong và sau hành động

Bài giảng

Guardrail không chỉ là một câu “hãy an toàn” trong system prompt. Nó nên được đặt ở boundary mà application có thể thực thi. Có thể kiểm tra input trước khi agent chạy, kiểm tra arguments trước tool execution và validate output trước khi trả người dùng.

USER INPUT ↓ input guardrail AGENT ↓ tool-call guardrail TOOL / SIDE EFFECT ↓ output/tool-result validation AGENT ↓ output guardrail FINAL

OpenAI Agents SDK phân biệt input, output và tool guardrails. Một điểm quan trọng: guardrail không tự hoàn tác side effect đã xảy ra bên ngoài. Vì vậy các hành động nguy cơ cao phải được kiểm tra trước khi thực thi.

Bài tập

  1. Chọn 10 tools của Media Agent.
  2. Viết precondition và postcondition cho mỗi tool.
  3. Tạo guardrail cho path traversal: không cho ghi ra ngoài workspace.
  4. Tạo guardrail cho file overwrite: mặc định không ghi đè.
  5. Tạo output validator kiểm tra artifact thật sự tồn tại.
  6. Viết 8 adversarial inputs để cố phá guardrails.

Deliverable: Guardrail Matrix + test report.

Nguồn

BÀI 24

Human in the Loop: quyền tự trị theo mức rủi ro

Bài giảng

Không phải mọi tool call đều cần hỏi người dùng. Nếu hỏi quá nhiều, agent mất giá trị; nếu không hỏi gì, side effects nguy hiểm. Ta cần policy dựa trên risk, reversibility, external impact và confidence.

GREEN → read-only, local, reversible → auto YELLOW → write local / significant change → log or confirm by policy RED → delete / publish / send / pay / external irreversible → approve

LangGraph hỗ trợ interrupts để pause execution, lưu state qua checkpointer và resume sau khi con người approve/edit/reject. OpenAI Agents SDK cũng cung cấp human-in-the-loop mechanisms. Kiến trúc quan trọng ở đây là việc pause/resume phải bền vững; không giữ process chạy vô thời hạn để chờ.

Bài tập

  1. Phân loại tất cả tool vào GREEN/YELLOW/RED.
  2. Viết approval payload gồm: action, target, arguments, expected effect, rollback.
  3. Giả lập user chọn approve, edit và reject.
  4. Lưu state trước approval rồi restart app; kiểm tra có resume được không.

Deliverable: Risk Policy + approval flow.

Nguồn

BÀI 25

Sandboxing và Principle of Least Privilege

Bài giảng

Khi agent có shell, Python hay filesystem write, sai lầm có thể biến từ “câu trả lời tệ” thành “hệ thống bị thay đổi”. Sandbox tạo môi trường cô lập, giới hạn filesystem, network, process, credentials và lifetime.

Không nên đưa toàn bộ máy local cho agent chỉ vì nó chạy local. Tạo workspace riêng, mount input read-only nếu có thể, output write-only theo folder, inject secret tối thiểu và không expose home directory mặc định.

HOST MACHINE └─ sandbox/workspace ├─ /input read-only ├─ /work read/write ├─ /output read/write └─ allowed commands only Secrets: only what this task needs Network: deny by default or allowlist

Google ADK có code execution tool dùng sandboxed environments; OpenAI Agents SDK có sandbox agent concepts cho isolated filesystem workspace. Dù framework nào, nguyên tắc cốt lõi vẫn là least privilege.

Bài tập

  1. Thiết kế threat model: agent bị prompt injection hoặc gọi lệnh sai thì mất gì?
  2. Định nghĩa filesystem boundary.
  3. Định nghĩa command allowlist cho FFmpeg/FFprobe/Python script.
  4. Không truyền API key vào command line log.
  5. Tạo test: agent cố đọc file ngoài workspace; hệ thống phải chặn.
  6. Tạo cleanup policy sau mỗi task.

Nguồn

OOpenAI Agents SDK TypeScript Overview: sandbox agents với isolated filesystem workspaces, shell/file editing và sandbox state.

GGoogle ADK Agent Runtime Code Execution: code execution trong sandbox, state persistence và isolation.

BÀI 26

Evaluation: agent tốt phải đo được

Bài giảng

Agent khó eval hơn chatbot vì kết quả phụ thuộc trajectory: model gọi tool nào, state thay đổi ra sao, retry thế nào và có hoàn thành task hay không. Evals nên có nhiều tầng: component eval cho router/tool selection, trajectory eval cho hành vi đa bước và end-to-end eval cho outcome.

EVAL STACK 1. deterministic checks: file exists, schema valid 2. component: router/tool selection accuracy 3. trajectory: correct steps, no unsafe call 4. outcome: task completed + quality rubric 5. operations: latency, tokens, cost, retries

Anthropic khuyến nghị evals có nhiệm vụ đại diện cho production, graders đáng tin cậy và failure analysis. Một golden dataset tốt không chỉ gồm case đẹp mà phải chứa edge cases và failure cases đã từng gặp.

Bài tập cuối chặng

  1. Tạo dataset 30 test cases cho Media Agent: 15 normal, 10 edge, 5 adversarial.
  2. Định nghĩa metrics: task success, tool accuracy, unsafe calls, retries, latency, estimated cost.
  3. Viết deterministic graders cho artifact/schema.
  4. Viết rubric cho chất lượng summary/description.
  5. Chạy baseline và ghi score.
  6. Thay prompt/tool description rồi chạy lại; chỉ giữ thay đổi nếu metrics không regress.

Deliverable: evals/ + baseline report + changelog.

Nguồn
