Tools & MCP

Tool là “tay chân” của agent. Chặng này tập trung vào cách thiết kế tool nhỏ, rõ, có schema và error semantics tốt; sau đó mới đặt tool vào MCP hay framework.

BÀI 10

Function Calling: nối LLM với hành động thật

Bài giảng

Function calling không có nghĩa model trực tiếp chạy code. Model sinh ra một yêu cầu có cấu trúc: tên tool và arguments. Runtime của ứng dụng kiểm tra yêu cầu, thực thi function thật, rồi đưa kết quả trở lại model. Điều này tạo ranh giới quan trọng giữa quyết định và thực thi.

USER → MODEL │ ├─ final answer └─ tool_call{name,args} ↓ APP validates ↓ FUNCTION/API ↓ tool_result ↓ MODEL

Tool input nên có schema rõ, dùng enum hoặc kiểu dữ liệu cụ thể khi có thể. Runtime không nên tin arguments tuyệt đối: cần validation, permission, path checks và timeout. Tool result cũng nên có cấu trúc, tránh trả hàng nghìn dòng log không cần thiết vào context.

Thực hành có code

Tạo ba Python function thuần, chưa dùng framework:

def get_video_metadata(path: str) -> dict: ...
def extract_audio(path: str, out_path: str) -> dict: ...
def list_media_files(folder: str) -> list[dict]: ...
  1. Định nghĩa JSON schema cho input/output.
  2. Viết validation: file tồn tại, extension hợp lệ, output nằm trong workspace.
  3. Giả lập một tool call bằng JSON rồi dispatch thủ công.
  4. Thử input lỗi và thiết kế error object có code, message, retryable.

Deliverable: file tools.py + 6 test cases.

BÀI 11

Tool Design: nhỏ, rõ và khó dùng sai

Bài giảng

Một tool tốt nên cho model “affordance” rõ: tên mô tả đúng hành vi, description nói khi nào dùng/không dùng, arguments đủ thông tin nhưng không dư, output ngắn và có ý nghĩa. Tool quá rộng như manage_video() khiến model phải đoán mode và dễ gọi sai; tool quá vụn lại làm tool surface phình to và tăng khó khăn lựa chọn.

Anthropic nhấn mạnh việc chọn đúng tool để triển khai, namespace tool rõ, trả information density cao và xây eval riêng cho tool. Một nguyên tắc hữu ích: tool nên tương ứng với một hành động có ranh giới rõ trong domain.

Xấu: do_everything(action, payload, mode, extra...) Tốt hơn: media.get_metadata(path) media.extract_audio(path,out) media.trim(input,start,end,out) media.render(spec,out)

Bài tập

  1. Viết danh sách 15 tool cho Media Agent.
  2. Nhóm theo namespace: filesystem.*, media.*, speech.*, content.*.
  3. Với từng tool ghi: purpose, use when, do not use when, input, output, side effects.
  4. Gộp các tool trùng chức năng; tách các tool “làm tất cả”.
  5. Tạo 20 câu hỏi và kiểm tra xem tên/description có đủ để chọn tool đúng không.

Deliverable: Tool Catalog v1 dưới dạng Markdown.

BÀI 12

Tool Router và quyền sử dụng tool

Bài giảng

Khi agent có nhiều tool, vấn đề không còn là “có tool hay không” mà là model có biết chọn đúng tool, đúng thời điểm và đúng arguments hay không. Tool router có thể là model tự chọn từ toàn bộ tool surface, hoặc application giới hạn tool khả dụng theo state/intent.

Giới hạn tool theo context thường an toàn hơn: đang ở bước phân tích thì chỉ expose read-only tools; bước render mới expose write tools; delete không expose mặc định. Đây là cách biến permission thành kiến trúc thay vì chỉ là lời nhắc trong prompt.

STATE = ANALYZE Tools: read metadata, transcribe, inspect STATE = EDIT Tools: trim, normalize, render STATE = PUBLISH Tools: upload (approval required)

Bài tập

  1. Lấy Tool Catalog bài 11.
  2. Gắn mỗi tool với states được phép gọi.
  3. Gắn risk: read-only / reversible write / irreversible external side effect.
  4. Thiết kế policy cho retry và approval.
  5. Viết 10 tình huống mà model chọn tool sai và cách kiến trúc ngăn lỗi trước khi tool chạy.

BÀI 13

MCP: chuẩn hóa cách agent tiếp cận context và tools

Bài giảng

Model Context Protocol (MCP) chuẩn hóa giao tiếp giữa ứng dụng AI và server cung cấp context/capability. Trong mô hình MCP server, ba primitive quan trọng là prompts, resources và tools. Theo specification: prompts thường do user chủ động chọn, resources do application quản lý, tools được model gọi để thực hiện hành động hoặc truy xuất.

HOST / AI APP │ MCP client ▼ MCP SERVER ├─ Prompts → mẫu tương tác ├─ Resources → dữ liệu/context └─ Tools → hành động/function

MCP không biến ứng dụng thành agent. Nó chỉ tạo interface chuẩn. Bạn vẫn phải thiết kế goal, loop, permission, state và evaluation. MCP đặc biệt hữu ích khi cùng một nguồn capability cần được nhiều client/agent dùng lại.

Mini project 3 — Video Inspector

  1. Xây Python app nhận đường dẫn video.
  2. Tool 1 lấy metadata bằng FFprobe.
  3. Tool 2 kiểm tra audio stream.
  4. Tool 3 kiểm tra resolution/frame rate.
  5. Đưa kết quả cấu trúc cho LLM để viết nhận xét.
  6. Sau khi bản local chạy ổn, mô tả cách ba tool trên có thể được expose qua MCP server. Không bắt buộc phải triển khai MCP ngay.

Deliverable: app chạy được + README + sơ đồ local function tools → MCP.
